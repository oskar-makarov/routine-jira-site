Recurring Workflows for Jira

Make recurring work a repeatable process.

Schedule Jira workflows with task hierarchies, relative due dates, dependencies, assignee rotations and run history.

  • Plan daily, weekly, monthly, quarterly, yearly or one-time workflows in your timezone.
  • Apply working days and excluded holiday dates.
  • Connect Jira tasks, owners, dependencies and due dates.
  • Start from an editable template for month-end close, onboarding, access reviews or maintenance.
  • Inspect run history and follow created issues into Jira.

Routine runs on Atlassian Forge without an external application backend. Jira remains the source of truth for projects, users and issues.

Scheduled execution is not an exact-to-the-minute guarantee. Available issue types and hierarchies depend on your Jira project. Marketplace availability and pricing will be announced after listing approval.

Support

Email routine@nonpr1zm.com.

Include your Jira site URL, Routine version, routine and run identifiers, the time and timezone of the problem, and the visible error message. Redact confidential workflow content and personal information. Never send passwords, API tokens or payment details.

Before running again

Check run history first. Another manual run creates another occurrence. If a creation result is uncertain, retain the history and contact support before manually recreating work. Routine may need to reconcile an existing Jira issue.

Project configuration

If a run fails, check project issue types, required fields, app permissions and assignee availability. Pausing stops future scheduled occurrences; existing recovery work and created Jira issues can remain. Deleting a routine removes its Routine data, not its Jira issues.

Support is provided by email without a guaranteed response time or service availability commitment.

Data and purpose

Routine processes routine names, workflow summary and description templates, labels, project and issue type references, Jira account identifiers for assignees, schedules, timezones, calendars, dependencies and rotation state. Run records contain configuration snapshots, timestamps, statuses, attempts, issue references and diagnostic errors.

Routine reads project, user and issue metadata from Jira and creates issues and dependency links according to the saved workflow. It does not store your Jira password or API token.

Hosting and access

Routine runs on Atlassian Forge with installation-scoped storage. It has no external application backend, advertising service or external analytics integration. App data is not sent to publisher-operated servers. Atlassian supplies hosting and platform services under its own policies.

Access to Routine definitions and run history requires the corresponding Jira project permissions. Mutations require additional permissions. Site settings require Jira administration permission. Scheduled execution uses the app's Jira permissions.

Retention and deletion

Completed run history older than 365 days is periodically pruned. Pending and recoverable runs can remain longer. Routine definitions remain until deleted. Deleting a routine removes its stored definition and history but does not delete Jira issues it created. Cleanup occurs in bounded operations and can require subsequent passes.

Minimal metadata for deleted routines, consisting of routine UUID, cleanup due time and queue key, remains until installation storage is purged. It supports cleanup of records delayed by storage indexes and contains no workflow text, assignee identifiers or Jira issue references.

After uninstall, Atlassian's Forge storage retention and deletion policies apply. Routine has no independent backup service outside Forge.

Diagnostics and support email

Application logs record operational identifiers, statuses, counts and error categories. Workflow text and Jira error content are not intentionally written to production logs. Run records can contain diagnostic messages visible to authorized users.

When you contact support, your email and the information you choose to send are processed separately to respond to your request. Email support is outside Atlassian Forge. Do not send secrets or confidential issue content.
